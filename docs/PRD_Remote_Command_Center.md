## 1. 배경 및 문제 정의

### 1.1 기업 프로파일

코힙스테크는 일반적인 단순 금속재가공을 넘어 **초고온/고압(최대 2000°C, 200MPa)** 기반의 HIP(열간등방압) 처리 및 가스 아토마이즈 등 매우 고정밀 첨단 소재 가공을 수행하는 강소기업이다.

- **핵심 제품**: Fuel Valve Nozzle Blank, 초경합금/인코넬 핵심 부품
- **주요 고객**: MAN Energy Solutions, 조선·항공·방산 분야
- **핵심 설비**: HIP 장비, 진공로(가스 아토마이저)
- **현재 업무 도구**: MS Office(Excel), 카카오톡
- **웹사이트**: [project-dpe0o.vercel.app](https://project-dpe0o.vercel.app/)

### 1.2 핵심 문제

CEO가 **출근 횟수를 줄이면서도 관리 통제력을 100% 유지**하고자 한다.

| 문제 | 현재 상태 | 영향 |
|------|----------|------|
| **정보 비대칭** | 현장 데이터가 엑셀/카톡에 분산되어 있어 CEO가 현장에 없으면 현황 파악 불가 | 의사결정 지연 |
| **결재 병목** | 원자재 발주, 견적서 승인 등이 대면/전화 기반 | 긴급 결재 누락, 납기 지연 |
| **이상 감지 지연** | 설비 이상·불량 발생 시 카톡 보고에 의존 | 대형 사고·품질 리스크 |
| **해외 고객 대응** | 영문 이메일/기술 규격 변경 보고가 비정기적 | MAN 등 핵심 고객 리스크 |

### 1.3 핵심 제약 조건

- 직원들이 **새로운 소프트웨어 도입에 대한 반발**이 큼 → 기존 [엑셀 + 카카오톡] 루틴 유지 필수
- 거창한 그룹웨어/ERP 도입은 **비용·교육 부담** 때문에 부적합
- **뒤에서만 AI가 작동**하게 만들어, 직원 행동 패턴을 급격히 바꾸지 않아야 함

## 2. 제품 비전

### 2.1 한 줄 요약

> **"현장은 평소대로 엑셀과 카톡을 쓰고, CEO는 스마트폰 하나로 공장을 운영한다."**

### 2.2 시스템 아키텍처 개요

```
[현장/사무직]                  [자동화 백엔드]                    [CEO]
카카오톡 텍스트/사진  ──→  MS Power Automate / Python  ──→  CEO 맞춤형 카톡 알림
MS Excel 작업일지    ──→  LLM (OpenAI API / Copilot)  ──→  핵심 이슈 브리핑 (오전 8시)
견적서/기안서 PDF    ──→  문서 분석/요약 엔진          ──→  전자결재 요청 [승인/반려]
HIP 챔버 로그        ──→  이상 감지 모듈              ──→  위험(Red) 플래그 즉시 알림
해외 고객사 이메일    ──→  영문 요약/중요도 판별        ──→  긴급 알림 + 국문 요약
```

### 2.3 핵심 설계 원칙

1. **Zero Learning Curve**: 현장 직원은 기존 도구(엑셀, 카톡)만 사용
2. **AI Invisible**: LLM은 백엔드에서만 동작, 사용자에게 노출되지 않음
3. **Mobile-First CEO**: CEO의 모든 의사결정은 카카오톡 또는 모바일 대시보드에서 가능
4. **Incremental Rollout**: 한 번에 전체 도입이 아닌 단계적 구축
5. **Existing Stack**: MS 365(Power Automate, OneDrive, SharePoint) 최대 활용

## 4. 핵심 기능 명세

### 4.1 모듈 A: CEO 대시보드 (Daily Command Briefing)

#### 목적
CEO가 매일 아침 1분 안에 공장 전체 현황을 파악할 수 있는 자동 요약 리포트

#### 기능 상세

| ID | 기능 | 설명 | 우선순위 |
|----|------|------|----------|
| A-1 | **일간 핵심 브리핑** | 매일 오전 8시, 전일 생산량·불량률·출하 현황을 요약한 'CEO 1페이지 핵심 리포트' 카톡 전송 | P0 |
| A-2 | **HIP 공정 품질 요약** | HIP 챔버 핵심 로그(온도, Ar 가스 압력, 유지 시간)와 Fuel Valve Nozzle 및 초경합금 당일 생산/불량 실적 1페이지 리포트 | P0 |
| A-3 | **주간 트렌드 리포트** | 주 1회(월요일 오전) 전주 대비 증감률, 누적 불량 패턴, 원자재 소모 트렌드 요약 | P1 |
| A-4 | **자연어 질의 응답** | CEO가 카톡으로 "오늘 B라인 불량 원인이 뭐야?" 질문 시 LLM이 엑셀 데이터를 재조회하여 답변 | P1 |
| A-5 | **웹 대시보드** | 모바일 최적화된 웹 대시보드에서 실시간 KPI 확인 (생산 수율, 설비 가동률, 결재 대기 건수) | P2 |

#### LLM 프롬프트 설계 (A-1 예시)

```
시스템 프롬프트:
"너는 코힙스테크(금속재가공 강소기업)의 공장장이다.
오늘 생산 실적과 지난주 평균을 비교하여 이상 지점을 3줄로 요약하라."

입력 데이터: [OneDrive 공유 엑셀에서 Power Automate가 추출한 당일 데이터]
출력 포맷:
📊 [일간 브리핑] 2026-08-09
• 생산량: XX개 (전일 대비 +/-%)
• 불량률: X.X% (기준 3% 이하 ✅/초과 🚨)
• 특이사항: [있으면 1줄 요약]
• 금일 결재 대기: N건
```

#### KPI

| 지표 | 목표값 |
|------|--------|
| 브리핑 전송 성공률 | ≥ 99% |
| CEO 브리핑 확인까지 소요 시간 | ≤ 30분 |
| 자연어 질의 응답 정확도 | ≥ 85% |

### 4.2 모듈 B: LLM 기반 원격 전자결재 (E-Approval)

#### 목적
CEO가 현장에 없어도 카카오톡에서 결재 요청을 검토하고 [승인/반려]를 즉시 처리

#### 결재 흐름

```
[직원] 공유 엑셀에 지출 내역 기입 or 견적서 PDF 업로드
        ↓
[Power Automate] 신규 항목 감지
        ↓
[LLM] 문서 읽기 → 요약 + 과거 데이터 대비 검토 의견 생성
        ↓
[CEO 카카오톡]
  💡 [결재 요청] 아르곤(Ar) 가스 충전 발주서
  - 비용: 000만 원 (전월 대비 동일)
  - LLM 검토: 현재 가동률 감안 시 적정 재고 확보를 위해 승인 권장
  버튼: [승인(결재진행)] / [반려]
        ↓
[CEO] 승인 클릭
        ↓
[시스템] 엑셀 상태 → '승인 완료' 자동 업데이트
[시스템] 담당자에게 카톡 → "결재 완료, 발주 진행하세요"
```

#### 기능 상세

| ID | 기능 | 설명 | 우선순위 |
|----|------|------|----------|
| B-1 | **결재 요청 자동 감지** | OneDrive 공유 엑셀 '결재요청' 시트에 신규 행 추가 시 Power Automate 트리거 | P0 |
| B-2 | **LLM 기안서 요약** | 기안서/견적서를 3줄로 요약 + 과거 단가 대비 분석 + 승인 권장 의견 | P0 |
| B-3 | **카톡 결재 버튼** | [승인(결재진행)] / [반려] 인터랙티브 버튼 제공 | P0 |
| B-4 | **결재 결과 자동 반영** | 승인 시 엑셀 상태 컬럼 업데이트 + 담당자 카톡 알림 | P0 |
| B-5 | **반려 사유 입력** | 반려 시 CEO가 한 줄 사유를 카톡으로 입력하면 기록 | P1 |
| B-6 | **긴급 결재 에스컬레이션** | 2시간 내 미처리 결재건 재알림 | P1 |
| B-7 | **견적·원가 검토 보조** | 과거 단가 엑셀 데이터 및 원자재 시세를 기반으로 적정 견적가 추정 및 손익 마진 검토 | P1 |
| B-8 | **월간 결재 리포트** | 당월 승인/반려 건수, 총 결재금액, 평균 처리시간 요약 | P2 |

#### 전자결재 대상 항목

| 결재 유형 | 설명 | 예상 빈도 |
|----------|------|----------|
| 원자재 발주 | Inconel, Ar가스, 특수 가스 등 고가 원부자재 | 주 2-3회 |
| 견적서 최종 승인 | 고객사 견적서 송부 전 마진 확인 | 주 1-2회 |
| 설비 유지보수비 | HIP 장비, 진공로 수리/부품 교체 | 월 2-3회 |
| 지출 결의서 | 기타 경비 지출 | 수시 |

#### KPI

| 지표 | 목표값 |
|------|--------|
| 결재 요청 → CEO 수신 시간 | ≤ 5분 |
| 평균 결재 처리 시간 | ≤ 2시간 (업무시간 기준) |
| 결재 누락률 | 0% |
| LLM 요약 정확도 | ≥ 90% |

### 4.3 모듈 C: 이상 감지 및 리스크 경보 (Anomaly Alert)

#### 목적
설비 이상, 품질 불량, 안전 리스크를 자동 감지하여 CEO에게 즉시 경고

#### 기능 상세

| ID | 기능 | 설명 | 우선순위 |
|----|------|------|----------|
| C-1 | **불량률 이상 감지** | 불량률 3% 초과 시 자동 원인 추정 + 우선 조치 사항 제안 | P0 |
| C-2 | **HIP 챔버 이상 감지** | 밀도/피로강도 불량 원인 추정, 장입 방식 오류 감지 | P0 |
| C-3 | **설비 키워드 모니터링** | 카톡/엑셀 비고란에서 "진공로 이상 소음", "압력 저하" 등 키워드 감지 시 즉각 '위험(Red)' 플래그 | P0 |
| C-4 | **원자재 손실 분석** | 설비 정지시간, 원자재 손실 이상치 분석 | P1 |
| C-5 | **안전 리스크 텍스트 분석** | 카톡/작업 일지의 텍스트에서 소음, 원자재 품질 문제 등 대형 사고 미리 경고 | P1 |

#### 알림 레벨 체계

| 레벨 | 조건 | 알림 방식 |
|------|------|----------|
| 🟢 **정상(Green)** | 모든 지표 기준치 이내 | 일간 브리핑에만 포함 |
| 🟡 **주의(Yellow)** | 불량률 2-3%, 설비 효율 저하 | 카톡 알림 (1일 1회 요약) |
| 🔴 **위험(Red)** | 불량률 3%+, 설비 이상 키워드 감지, 안전 이슈 | **즉시 카톡 전송** + 전화 알림 권장 |

#### 카카오톡 보고 규칙화 (현장 입력 표준)

현장에서 이슈 보고 시 간단한 말머리 키워드를 사용하도록 제도를 정립:

```
[설비고장] HIP 2호기 압력 저하 발생
[불량발생] 노즐 블랭크 밀도 미달 5건
[출하지연] A사 납기 2일 지연 예상
[안전] 3공장 가스 배관 이상 소음
```

#### KPI

| 지표 | 목표값 |
|------|--------|
| Red 알림 → CEO 수신 | ≤ 3분 |
| 이상 감지 정확도 (True Positive) | ≥ 80% |
| 오탐률 (False Positive) | ≤ 15% |

#### 목적
해외 고객사(MAN Energy Solutions 등)의 영문 이메일·기술 규격 변경을 자동 요약하고 긴급도 판별

#### 기능 상세

| ID | 기능 | 설명 | 우선순위 |
|----|------|------|----------|
| D-1 | **영문 이메일 자동 요약** | 해외 고객사 영문 이메일을 국문 3줄 요약 + 중요도(High/Low) 판별 | P1 |
| D-2 | **기술 규격 변경 감지** | 규격서 변경 사항을 이전 버전과 비교하여 핵심 변경점 추출 | P2 |
| D-3 | **클레임 리스크 조기 경보** | 고객사 이메일 톤 분석 + 키워드 기반으로 클레임 가능성 사전 알림 | P2 |

### 5.1 데이터 수집 경로

```
┌─────────────────────────────────────────────────────────────┐
│                    데이터 소스 (현장)                          │
├───────────────────┬───────────────────┬─────────────────────┤

└────────┬──────────┴────────┬──────────┴──────────┬──────────┘
         │                   │                      │
         ▼                   ▼                      ▼
┌─────────────────────────────────────────────────────────────┐
```

## 7. 구현 로드맵

### Phase 1: 데이터 및 결재 양식 클라우드화 (1–2주)

**목표**: 현장 데이터를 LLM이 접근 가능한 형태로 표준화

| 작업 | 담당 | 산출물 |
|------|------|--------|
| 생산일지 엑셀 양식 통일 (셀 위치 고정) | 현장 관리자 + IT | 표준 엑셀 템플릿 |
| 로컬 PC 엑셀 → OneDrive 공유 엑셀 이전 | IT | 클라우드 엑셀 |
| HIP 장비 장입 기록, 생산 일지, 지출 결의서 양식 이전 | 현장 관리자 | OneDrive 폴더 구조 |
| 카카오톡 보고 말머리 키워드 제도 수립 | 관리자 | 보고 가이드 문서 |
| 업무용 카카오톡 채널 분리 (결재요청방, 일일보고방, 긴급이슈방) | 관리자 | 3개 카톡 채널 |

### Phase 2: LLM 원격 전자결재 파이프라인 구축 (2–3주)

**목표**: 결재 요청 → LLM 분석 → CEO 카톡 알림 → 승인/반려 → 자동 반영

| 작업 | 담당 | 산출물 |
|------|------|--------|
| Power Automate 플로우: 엑셀 신규 행 감지 → LLM API 호출 | IT/개발 | Automate 플로우 |
| LLM 프롬프트 튜닝 (결재 요약 + 과거 단가 비교) | IT/개발 | 프롬프트 셋 |
| 카카오톡 알림톡 API 연동 (인터랙티브 버튼) | 개발 | 알림톡 템플릿 |
| 승인/반려 콜백 → 엑셀 상태 자동 업데이트 | 개발 | Webhook |
| 일간 브리핑 자동 생성 파이프라인 | 개발 | Automate 플로우 |
| CEO 자연어 질의 응답 채널 구축 | 개발 | 카톡 챗봇 |

### Phase 3: 장비 이상 감지 대시보드 구축 (1–2주)

**목표**: 이상 징후 실시간 모니터링 + 웹 대시보드 MVP

| 작업 | 담당 | 산출물 |
|------|------|--------|
| 키워드 기반 이상 감지 모듈 (카톡/엑셀 비고란 텍스트 분석) | 개발 | Python 모듈 |
| 불량률 임계치 자동 알림 설정 | 개발 | Automate 규칙 |
| HIP 챔버 로그 분석 (밀도/피로강도 불량 원인 추정) | 개발 | 분석 모듈 |
| 웹 대시보드 MVP (생산 KPI, 결재 이력, 설비 상태) | 개발 | Next.js 앱 |
| CEO 사용성 테스트 및 피드백 반영 | CEO + 개발 | 개선 리스트 |

### Phase 4: 고도화 (4주+)

| 작업 | 설명 |

## 부록 B: 정합성 확보를 위한 CEO 확인 질문

PRD를 고도화하기 위해 CEO에게 확인이 필요한 사항:

1. **전자결재의 주요 범위**: 원자재/특수 가스 발주 결재인가요, 고객사 견적서 송부 전 최종 승인까지 포함인가요?
2. **HIP 및 진공로 설비 데이터 연동**: 현재 HIP 장비나 진공로의 데이터(온도/압력 변화 그래프 등)가 USB나 엑셀로 자동 추출되나요, 아니면 작업자가 게기판을 보고 수기로 적나요?
3. **MS 365 클라우드 환경 여부**: 단순히 엑셀을 PC에 깔아서 쓰시는지, 아니면 MS 365를 구독하여 OneDrive, Teams, SharePoint 등의 클라우드 기능을 이미 활용할 수 있는 상태이신지?
4. **원격 모니터링 1순위 지표**: 매일 가장 먼저/가장 중요하게 확인하고 싶으신 수치는? (예: 노즐 블랭크 생산 수율, 특정 합금의 밀도 검사 패스율, 설비 가동시간 등)
